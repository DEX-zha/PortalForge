# PortalForge project prerequisites

The user requires an operational Dolphin MCP as a preliminary step in project creation.

- Read `docs/mcp/dolphin-mcp.md` before planning or implementing SSA archive/level features, and `docs/format/iga-v4.md` before touching archive code.
- Gates: `node tools/ssa-archive/cli.mjs gates` prints M0..M5 from `docs/m*-status.json`. M0, M1 and M2 are PASS (2026-09-12), so size-preserving edits of CONFIRMED properties are permitted (FR-016). M3 is PASS (2026-09-13, `docs/m3-status.json`): a record is instantiated when a same-size replacement puts the copy in a slot the count-bounded walk already visits — never by insertion, which shifts every later walker. Visible duplication and in-place transform edits of placements are CONFIRMED (`igz.placement.type104-record`, `level.prop.scriptset-placement`), so `ssa-archive edit list|show|set|replace` may move, retexture and duplicate props; see `docs/format/igz-level-editing.md` for the limits (scripted placements, shared model records). Geometry, collision and gameplay changes wait for M4A, M4B and M5. The constitution (`.specify/memory/constitution.md`) records these invariants.
- Never infer readiness from `tools/list`, a process launch, a scheduled action, a successful boot of a Riivolution descriptor, or an empty/black screenshot alone. Consumption of a replaced file is proven by Dolphin's file monitor size line or a memory read; the rebuilt variants used for M1 are byte-different on purpose so the monitor can tell them apart.
- Preserve the original WBFS and the existing Dolphin 2606a installation (never drive the user's own Dolphin process). Use the dedicated `.local/` profiles and replacement files for experiments.
- Do not commit game data, figures, saves or memory dumps. Local evidence stays in `.local/`. The single exception is the curated illustration set in `docs/images/` — the logo, one editor capture and three in-game evidence frames published with the README on the user's request; do not extend it without being asked.
- Native additions have separately confirmed recipes (`level.prop.native-addition`, `-barrel`, `-chompy`, `-coin`, `-expanded`, `-capacity`, 2026-09-16): SSPP52 Rev1 tutorial, nine exact sources listed in `specs/005-native-object-addition/compatibility.md`, at most eight additions total, XYZ/heading, scale100. Eight mixed additions passed two identical cold boots. Scripted creation waits for a populated native activation-observer list and the tutorial anchor; source scripts, IDs and activation ranges are retained. Use the editor-generated Gecko accompaniment and editor-owned launch; validate factory/activation fingerprints and distinct native instances. Check initial transforms separately from current AI/animation transforms, and creation separately from final survival. Restore the research profile after confirmed stop. Family tests do not grant Add automatically; other source parameters, full combat/collection semantics, persistence outside activation range, scale changes and level reload in the same emulation are unvalidated. This does not authorize IGZ insertion or advance M4A/M4B/M5.
- Add anything, verified at launch (feature 007, constitution 1.2.0, `specs/007-unlimited-additions/`): any resident object of a level whose place in memory is known can be added, stored templates and objects with nothing to draw included. A source with its own CONFIRMED recipe is a confirmed addition; any other is an **experimental addition** (`experimental: true` in the session, the sidecar and the patch), created from the activation manager hook and never called confirmed. Every run that carries additions reads each of them back from memory (`inspectAdditions` in `native-run.mjs`) at the captures of the level, during play and at the end, and `addition-reports.mjs` files the verdict per family (`.local/addition-validation/<family>.json`, with its launches): the card says verified in game, failed in game with the reason, or not verified yet. A run with experimental additions does not fail when one is missing. The recipe's level bindings are data (`native-params.mjs`): the tutorial's constants, or the base and a still, visible, script-less active placement from the level's newest scene snapshot (Mining: base 0x80DC6F48, anchor MineTrain); a level never measured patches `layout: 'live'` instead: a routine with an empty 59-row table, the same bytes for every level, whose count, anchor and rows the launch writes into the running game through the bridge once it has measured the level at the first capture of it (`native-live.mjs`: rows, anchor, then count; the routine idles while the count is zero), keeping the measure as the level's scene snapshot (two identical boots on Undead Volcano, `level.prop.native-addition-live-table`, LIKELY). A scene of more than 59 additions also patches the live routine, measured level or not: `writeLiveBatches` writes one table of rows at a time, waits for the routine to attempt them, keeps what it wrote (attempt word and instance, in `options.rows`, which `locateAdditionRows` answers from) and writes the next batch over them; the editor accepts 590 (`ADDITION_LIMIT`, a guard, not a measure), and such a scene creates nothing when played without the editor. What a run does about its additions lives in `native-watch.mjs`, not in `runEditorGame`. Memory can be reserved from the game through the OS arena (`runtime.memory.mem2-arena-reservation`, LIKELY: a Riivolution `<memory>` patch lowers the end of usable MEM2 at 0x80003128 before the game's first instruction; 256 KB stayed intact on two boots and were overwritten entirely in the control; `buildPatchWorkspace({ memory })` is research only, and a checkpoint's identity covers what a patch writes into memory); no table lives there yet. The Project tab files objects by what the game says about them (`object-kinds.mjs`: library layer and script directory, never a display name) and a kind is a model path plus a script path within the game Content tree; `edit catalogue` builds the game-wide catalogue under `.local/catalogue/` (8 800 kinds in 75 levels) that the Whole game scope shows; a kind held only by other levels is a read-only card without an offset, so nothing of another level can reach a scene before phase C imports it. The bridge reads at most 64 KB per call. Other levels use `context: 'activation'` for every source. The Gecko budget is 3 256 bytes (the code list starts at 0x80002338): 18 additions with the proven 144-byte slot, 59 with `layout: 'table'` (40-byte rows, one shared argument block rebuilt before each call); the editor switches to the table past 18. The tutorial's compiled bytes are pinned by sha256 in `tests/editor-native-levels.test.mjs`: do not change them. `research-probes/native-level-probe.mjs` runs a batch of sources in one boot (`--auto N --visible --layout table`), `research-probes/activation-flag-boot.mjs` flips the +0x54 word on a copy; tests of campaigns must pass `outDir` and `reports` so that nothing lands in `.local/`. Objects whose script removes them (debris, dead automaton parts, closing-cutscene actors) read as created then gone: that is their script, not a failed creation.
- Game-mod descriptor paths must use forward slashes, and Riivolution `external` paths must start with `/` (root-relative); otherwise Dolphin silently serves the original file. Use `buildPatchWorkspace` from `tools/ssa-archive/src/patch/riivolution.mjs`.
- Direct tutorial entry has a separate confirmed strategy (`level.entry.preload-checkpoint`, `docs/editor/direct-entry.md`). Prepare before level load without Gecko on the matching Riivolution virtual disc; bind state/game/runtime/bridge/figure/configuration/layout and verify the FST before/after restore. Load the figure before restoring, then reconnect Wii input and trigger the level transition. Prove current archive consumption after restore. Never restore an already loaded level or native-initialized state to preview a new patch. Other levels remain UNKNOWN in `docs/level-entry-status.json`.
- Any of the 76 levels opens by name (`edit levels`, `edit open <level>`, `POST /api/open`; `specs/006-multi-level-editing/`): the original is extracted and the workspace decoded on first use under `.local/`, the level entry is found by name in the manifest, never by index. Every level carries capabilities with the finding behind each: transforms outside the tutorial are CONFIRMED on Mining (`level.transform.other-levels`, two identical boots with lowered lanterns on 2026-09-17) and LIKELY on levels not booted with an edit, duplication needs a runtime map (`runtime_maps` in `.local/dolphin-config.json`, else `.local/dolphin-evidence/runtime-maps/<lowercase name>.json`), native additions and the tutorial macro stay tutorial-only. Direct entry on another level is the archive redirect (`level.entry.archive-redirect`, CONFIRMED on Mining by two identical boots on 2026-09-17): the level's `.bld` and `.arc` are served under `level/Level_027_Tutorial.bld` and `.arc` through the confirmed tutorial checkpoint, offered as a direct launch mode once the voice pack is extracted; each level's confidence is its row in `docs/level-entry-status.json` (Mining CONFIRMED, other families LIKELY until two boots land in one of their levels). `research-probes/redirect-boot.mjs` runs one such boot through the editor's own path. Parked objects (boss cameras at 30480,30480,30480, switch templates near z = -815) are excluded from the framing extent by `levelExtent`, never from the level. Stored templates and inactive objects are bit 0 of the placement word +0x54 (4 placed, 5 stored; in RAM 1 active with actor, 2 placed without actor, 5 never instantiated), read on every level with the detected class by `scene-roles.mjs` (`igz.placement.inactive-flag`, LIKELY): they are drawn only in the hidden "Templates and disabled objects" layer, and an object seen "misplaced" at the origin or outside the level is almost always one of them. `research-probes/instance-probe.mjs` reads such records in MEM1 on a level reached through the redirect (`--all` reads every record: on Mining at the first playable frame 313 are dormant, 60 active, 8 finished initialisers, and only 3 objects have moved). The game-time view (`src/editor/scene-snapshot.mjs`, `level.runtime.scene-snapshot`, LIKELY): `POST /api/snapshot` while an editor-owned run is playing reads the resident section (found by a placed record's stored position triple) and scans MEM1 for placement instances created at run time (class pointer 0x80481674 outside the section, paired with their template by model and script; on Mining 11 such clones at the first frame, the cannon, push-block art, fan blades, pick, key); the As in game layer draws it, nothing is written. A clone's +0x5C names its template, not its creator. Script diagnostics now detect the script class and clone-list structures per file (`src/igz/script.mjs`, `src/editor/script-diagnostics.mjs`): an offline pass read every header-table script without a layout issue in 75 levels (20 distinct class indices); clone resources are found in Tutorial, Mining and Castle. This is read-only evidence, not proof that scripts can be imported between levels. Do not promote a capability for another level without two identical boots on that level.
- Findings live in `docs/findings/records/*.json` with CONFIRMED / LIKELY / UNKNOWN labels; only CONFIRMED findings may be marked editable. Render docs with `node cli.mjs findings render`; never edit the generated Markdown.
- In-game runs: `dolphin_frame_advance` waits at least N frames (15 s bound); heavy disc loads (Title.arc, global.arc) stall frames for a minute or more, so waits and captures tolerate consecutive timeouts. `Plus` pauses the game. Dolphin panic alerts are disabled in the research profile (`UsePanicHandlers = False`) because they pause emulation. State slots are 1..10 through the native UI.

Local checks: `npm test` from `tools/dolphin-mcp` and from `tools/ssa-archive`; `npm run lint` and `npm run format:check` from the repository root (run `npm ci` there once). CI runs all of them, and `npm run format` fixes formatting. Machine-specific paths (game image, figure, DolphinTool, the official Dolphin) belong in `.local/dolphin-config.json`, never in the source. Real-game tests: `node live-test.mjs` (MCP), `npm run proof` (M0), and from `tools/ssa-archive`: `node cli.mjs experiment explore|m1|m2|live-probe` (each boot to the tutorial takes about 4.6 min; records under `.local/dolphin-evidence/experiments/`).

# PortalForge project prerequisites

The user requires an operational Dolphin MCP as a preliminary step in project creation.

- Read `docs/mcp/dolphin-mcp.md` before planning or implementing SSA archive/level features, and `docs/format/iga-v4.md` before touching archive code.
- Gates: `node tools/ssa-archive/cli.mjs gates` prints M0..M5 from `docs/m*-status.json`. M0, M1 and M2 are PASS (2026-09-12), so size-preserving edits of CONFIRMED properties are permitted (FR-016). M3 is PASS (2026-09-13, `docs/m3-status.json`): a record is instantiated when a same-size replacement puts the copy in a slot the count-bounded walk already visits — never by insertion, which shifts every later walker. Visible duplication and in-place transform edits of placements are CONFIRMED (`igz.placement.type104-record`, `level.prop.scriptset-placement`), so `ssa-archive edit list|show|set|replace` may move, retexture and duplicate props; see `docs/format/igz-level-editing.md` for the limits (scripted placements, shared model records). Geometry, collision and gameplay changes wait for M4A, M4B and M5. The constitution (`.specify/memory/constitution.md`) records these invariants.
- Never infer readiness from `tools/list`, a process launch, a scheduled action, a successful boot of a Riivolution descriptor, or an empty/black screenshot alone. Consumption of a replaced file is proven by Dolphin's file monitor size line or a memory read; the rebuilt variants used for M1 are byte-different on purpose so the monitor can tell them apart.
- Preserve the original WBFS and the existing Dolphin 2606a installation (never drive the user's own Dolphin process). Use the dedicated `.local/` profiles and replacement files for experiments.
- Do not commit game data, figures, saves or memory dumps. Local evidence stays in `.local/`. The single exception is the curated illustration set in `docs/images/` — the logo, one editor capture and three in-game evidence frames published with the README on the user's request; do not extend it without being asked.
- Native additions have separately confirmed recipes (`level.prop.native-addition`, `-barrel`, `-chompy`, `-coin`, `-expanded`, `-capacity`, 2026-09-16): SSPP52 Rev1 tutorial, nine exact sources listed in `specs/005-native-object-addition/compatibility.md`, at most eight additions total, XYZ/heading, scale100. Eight mixed additions passed two identical cold boots. Scripted creation waits for a populated native activation-observer list and the tutorial anchor; source scripts, IDs and activation ranges are retained. Use the editor-generated Gecko accompaniment and editor-owned launch; validate factory/activation fingerprints and distinct native instances. Check initial transforms separately from current AI/animation transforms, and creation separately from final survival. Restore the research profile after confirmed stop. Family tests do not grant Add automatically; other source parameters, full combat/collection semantics, persistence outside activation range, scale changes and level reload in the same emulation are unvalidated. This does not authorize IGZ insertion or advance M4A/M4B/M5.
- Game-mod descriptor paths must use forward slashes, and Riivolution `external` paths must start with `/` (root-relative); otherwise Dolphin silently serves the original file. Use `buildPatchWorkspace` from `tools/ssa-archive/src/patch/riivolution.mjs`.
- Direct tutorial entry has a separate confirmed strategy (`level.entry.preload-checkpoint`, `docs/editor/direct-entry.md`). Prepare before level load without Gecko on the matching Riivolution virtual disc; bind state/game/runtime/bridge/figure/configuration/layout and verify the FST before/after restore. Load the figure before restoring, then reconnect Wii input and trigger the level transition. Prove current archive consumption after restore. Never restore an already loaded level or native-initialized state to preview a new patch. Other levels remain UNKNOWN in `docs/level-entry-status.json`.
- Findings live in `docs/findings/records/*.json` with CONFIRMED / LIKELY / UNKNOWN labels; only CONFIRMED findings may be marked editable. Render docs with `node cli.mjs findings render`; never edit the generated Markdown.
- In-game runs: `dolphin_frame_advance` waits at least N frames (15 s bound); heavy disc loads (Title.arc, global.arc) stall frames for a minute or more, so waits and captures tolerate consecutive timeouts. `Plus` pauses the game. Dolphin panic alerts are disabled in the research profile (`UsePanicHandlers = False`) because they pause emulation. State slots are 1..10 through the native UI.

Local checks: `npm test` from `tools/dolphin-mcp` and from `tools/ssa-archive`; `npm run lint` and `npm run format:check` from the repository root (run `npm ci` there once). CI runs all of them, and `npm run format` fixes formatting. Machine-specific paths (game image, figure, DolphinTool, the official Dolphin) belong in `.local/dolphin-config.json`, never in the source. Real-game tests: `node live-test.mjs` (MCP), `npm run proof` (M0), and from `tools/ssa-archive`: `node cli.mjs experiment explore|m1|m2|live-probe` (each boot to the tutorial takes about 4.6 min; records under `.local/dolphin-evidence/experiments/`).
